# 网站：一个仓库，多个项目，互不干扰

本仓库的 GitHub Pages 站点按项目分子目录，每个项目独立构建、独立发布：

| 地址 | 项目 | 工作流 |
| --- | --- | --- |
| `/` | 项目目录页（自动生成） | `site-index.yml` |
| `/quadrant/` | 四象限任务计划 | `quadrant.yml` |
| `/weekly/` | GitHub 热榜周刊 | `weekly.yml`（出刊：`weekly-issue.yml`） |

## 为什么互不干扰

- **只在自己的目录变化时运行**：每个项目的工作流只监听自己的文件夹。改四象限不会触发周刊，反之亦然。
- **失败只影响自己**：一个项目测试或构建失败，就不发布；其他项目在线上的版本不受影响。
- **发布只替换自己的子目录**：站点内容存在 `gh-pages` 分支，发布时只替换 `/<项目>/`，别的目录原样保留（`publish-pages.yml` + `publish.sh`）。多个项目同时发布会自动排队。
- **离线缓存各管各的**：每个应用的 Service Worker 只覆盖自己的子目录。

## 加一个新项目

1. 在仓库根目录建文件夹，比如 `my-app/`。构建结果里要有 `index.html`，资源路径用相对路径（Vite 设置 `base: './'`）。
2. 在 `pages/projects.json` 里加一项（`path` 就是网址里的目录名，只能用小写字母、数字和连字符）：
   ```json
   { "path": "my-app", "title": "我的应用", "description": "一句话介绍" }
   ```
3. 复制 `.github/workflows/quadrant.yml` 为 `my-app.yml`，把里面的 `quadrant` 换成 `my-app`，按需调整构建命令和产物目录。

推到 main 后，它会出现在 `/my-app/`，首页目录也会自动加上它。

## 文件

- `projects.json`：项目列表，生成首页用
- `publish.sh`：把一个项目的构建结果放进站点目录
- `build-root.mjs`：生成首页、根目录的 `sw.js`（清理四象限搬家前留下的旧离线缓存）

## 关于四象限搬家

四象限原来在站点根目录，现在搬到了 `/quadrant/`。任务数据存在浏览器本地，按域名保存，搬家后仍在。旧的离线缓存会在下次打开时自动清掉。已经“安装到桌面”的旧版从根目录启动时，会自动跳到新地址；也可以在新地址重新安装一次。
