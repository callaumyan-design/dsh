# 真实设备验证指南

本项目的协议实现依据官方固件源码，自动化测试使用的是按源码编写的 **固件模拟器（Mock BLE）**。
Mock 测试通过 **不等于** 真实硬件验证。请按本指南在实机上逐项验证，并把结果记录下来
（建议附上诊断页导出的脱敏日志）。

> 原则：从只读开始。只有前面的只读项全部通过，再测试写操作；写操作先用不重要的 Profile。

## 准备

- 电脑：Windows 10/11、macOS、Linux 或 ChromeOS，蓝牙已打开；或 Android 手机。
- 浏览器：桌面版 Chrome / Edge（较新版本），或 Android 版 Chrome。
- 关闭手机上的 9eSIM 微信小程序（避免它占用 BLE 连接），读卡器通电、蓝灯闪烁。
- 本地运行：`npm install && npm run dev`，打开 http://localhost:5173 。
- 打开诊断页 → 日志，勾选“调试”可以看到每个通知分片的长度。

### 若通知被截断（MTU 问题）

固件每次 notify 256 字节，需要 ATT MTU ≥ 259。网页无法设置 MTU，由操作系统协商。
如果诊断页显示最大分片小于 256 且有“不完整（丢弃）”的消息：

1. 记录系统与浏览器版本、最大分片大小；
2. 换一台电脑或改用 Android Chrome 再试；
3. 短回复（getElpaInfo 约 300 字节）也可能受影响，此时协议识别会超时。

## 第五阶段：USB 串口日志（排查写入失败）

1. 用 USB-C 数据线连接读卡器与电脑（Windows 应出现 CH340 COM 口）。
2. 诊断 → USB 串口 → 连接串口（读卡器可能会重启，所以先连串口再连蓝牙）。
3. 连接蓝牙，重现问题（例如下载）。
4. 导出串口日志。页面会自动标出卡片返回的异常状态字（如 `6A84` 存储空间不足、`6A80` 数据错误）以及读卡器与卡片之间的传输失败。
